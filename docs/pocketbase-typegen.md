# PocketBase type generation

F01 evaluates `pocketbase-typegen` `1.5.0` with PocketBase `0.40.3`, the
PocketBase JavaScript SDK `0.28.1`, Node.js `24.20.0`, and TypeScript `7.0.2`.
The unmodified generator reads the representative schema and produces
deterministic output, but it does not pass the auth-create compatibility gate.

The compatibility fixture is an integration-only JavaScript migration under
`tests/fixtures/pocketbase-typegen/migrations/`. The generation script applies
it to a fresh operating-system temporary SQLite database for every run, then
invokes the generator with `--db`. It never uses the development database,
production migrations, a live API, or PocketBase credentials. The fixture
covers text, number, boolean, date, select, JSON, file, relation, and auth
fields. Compile-time assertions cover create, update, and expanded relation
types.

The generated auth record includes PocketBase's hidden, autogenerated
`tokenKey` field. Its `CreateAuth<T>` utility consequently requires
`tokenKey`, even though a valid PocketBase auth create payload must not provide
that server-managed field. The reproducible compatibility test compiles such a
valid auth create payload against generated output and requires the expected
TypeScript failure. F01 therefore defers generator adoption and uses the
hand-written compile-time types in `src/types/pocketbase-types.ts`.

Run the compatibility check with:

```sh
vp run types:compatibility
```
